Десктопная утилита для мониторинга производительности, диагностики зависаний и оперативного администрирования серверов **1С:Предприятие 8** на Windows.

---

## Возможности

### Мониторинг и диагностика
- **Рабочие процессы `rphost`**: отслеживание CPU, RAM (`WorkingSet`), количества сеансов, среднего времени вызовов и запросов к БД, автоматический расчёт индекса риска (`0–100`) и текстового диагноза.
- **Сеансы пользователей через `rac.exe`**: состояние (активный/спящий/выполняет вызов), база, приложение, хост, память и CPU-время RAC, нагрузка и I/O за последние 5 минут, блокировки (`blocked-by-dbms` / `blocked-by-ls`), оценочная доля CPU пользователя.
- **Технологический журнал (ТЖ)**: парсинг последних `.log`-файлов для сопоставления сеансов с контекстом документа (`Context=`) и длительностью последнего вызова.
- **Системные ресурсы сервера**:
  - Дисковая подсистема через Windows PDH (`PhysicalDisk (_Total)`: `% Disk Time`, скорость чтения/записи, средняя длина очереди).
  - Сетевые интерфейсы (входящий/исходящий трафик, утилизация, количество активных адаптеров).
  - Определение аппаратной среды: тип сервера/гипервизор (VMware, Hyper-V, KVM, Xen и др.), модель CPU, физическая RAM, тип накопителей (`NVMe`/`SSD`/`HDD`) и свободное место на томах.
- **Умный поиск и запуск `rac.exe` / `ras.exe`**: автоопределение пути из служб `ragent.exe` в реестре (64/32-бит), запущенных процессов, каталогов установки и дисков; автоопределение кодировки вывода RAC (`UTF-8`, `Windows-1251`, `CP866`); встроенный запуск `ras.exe`.

### Управление и автоматизация
- **Плавный вывод `rphost` (`process turn-off`)**:
  - Ручной вывод выбранного процесса.
  - Автоматический вывод при длительном превышении порога памяти с защитой от срабатывания ниже минимального числа `rphost`, паузой (cooldown) и ожиданием завершения активных вызовов.
- **Администрирование (с защитой контрольными фразами)**:
  - Завершение всех сеансов, всех кроме Конфигуратора, ранних дубликатов или спящих сеансов.
  - Включение/выключение регламентных и фоновых заданий (`scheduled-jobs-deny`) по информационным базам (включаются обратно только те базы, которые были выключены этим монитором).
  - Перезапуск служб 1С (`ragent.exe`) и аварийное завершение `rphost.exe`.
- **Отчётность и история**:
  - Экспорт автономного HTML-отчёта на рабочий стол (включает карточки, таблицы процессов/сеансов/тревог и до 5000 точек истории).
  - Автоматический суточный HTML-отчёт (ежедневно в `23:55`) с почасовой динамикой и рейтингом пользователей, генерировавших нагрузку.
  - Постоянная запись метрик в суточные CSV-файлы.

## Требования

### Для запуска на сервере 1С
- **ОС**: Windows 10 / Windows 11 / Windows Server 2016+ (`x64` или `x86`).
- **Права**: запуск **от имени администратора** (необходим для доступа к PDH-счётчикам, свойствам служб, управлению `ras.exe`/службами и `taskkill`).
- **Платформа 1С:Предприятие 8**: наличие утилит `rac.exe` и `ras.exe` на сервере и запущенного `ragent.exe`.
- При использовании self-contained сборки установка .NET Runtime на сервер не требуется.

### Для сборки из исходного кода
- [.NET 8.0 SDK](https://dotnet.microsoft.com/download/dotnet/8.0)

## Быстрый старт

1. Скачайте релизный архив для вашей архитектуры (`win-x64` или `win-x86`) из раздела **Releases** или соберите проект из исходников.
2. Запустите `1C-Server-Monitor.exe` **от имени администратора** на сервере 1С.
3. Перейдите на вкладку **Настройки**:
   - При необходимости нажмите **Запустить RAS** (если служба/процесс `ras.exe` ещё не запущены).
   - Если кластер защищён учётной записью администратора кластера, укажите имя администратора (и пароль, если он задан).
   - При необходимости укажите каталог технологического журнала (например, `D:\1C-TechLog`).
   - Нажмите **Сохранить и проверить**.
4. Контролируйте нагрузку на вкладках **Обзор** и **Пользователи и сеансы**. При инцидентах используйте кнопку **Отчёт HTML** для сохранения снимка состояния.

## Конфигурация и данные программы

| Назначение | Путь по умолчанию |
|---|---|
| Настройки (пароль кластера **не сохраняется** на диск) | `%LocalAppData%\1CServerMonitor\settings.json` |
| Суточная история метрик (CSV) | `%LocalAppData%\1CServerMonitor\history\history-YYYY-MM-DD.csv` |
| Диагностика RAC (при пустом ответе/ошибках привязки PID) | `%LocalAppData%\1CServerMonitor\last-rac-diagnostic.txt` |
| Суточные HTML-отчёты | `%UserProfile%\Documents\1CServerMonitor\Reports\1C-daily-<SERVER>-YYYY-MM-DD.html` |
| Разовые HTML-отчёты | `%UserProfile%\Desktop\1C-monitor-YYYYMMDD-HHMMSS.html` |

### Интервалы опроса по умолчанию
- Локальные метрики (`rphost`, диск, сеть): **5 сек**
- Опрос `rac.exe`: **15 сек**
- Сканирование техжурнала: **60 сек**
- Запись истории на диск (CSV): **60 сек**
- Подавление повторных одинаковых тревог: **300 сек**

### Контрольные фразы для опасных действий
- `ПОДТВЕРЖДАЮ` — завершение сеансов, управление фоновыми заданиями, плавный вывод `rphost`, перезапуск служб 1С.
- `УБИТЬ RPHOST` — принудительное завершение всех процессов `rphost.exe` (`taskkill /F /IM rphost.exe`).

## Сборка из исходного кода

### Обычная сборка (Debug / Release)
```bash
dotnet restore OneCMonitor.sln
dotnet build OneCMonitor.sln -c Release
```

### Публикация автономного single-file `.exe`
Для Windows x64:
```bash
dotnet publish OneCMonitor/OneCMonitor.csproj -c Release -r win-x64 --self-contained true -o artifacts/win-x64
```

Для Windows x86:
```bash
dotnet publish OneCMonitor/OneCMonitor.csproj -c Release -r win-x86 --self-contained true -o artifacts/win-x86
```

Или через PowerShell-скрипт в корне репозитория (собирает обе архитектуры и формирует `SHA256SUMS.txt`):
```powershell
.\scripts\publish.ps1
```
