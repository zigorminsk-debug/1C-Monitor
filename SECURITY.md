# Политика безопасности

## Сообщение об уязвимостях

Если вы обнаружили уязвимость безопасности в **1C Server Monitor**, пожалуйста, **не создавайте публичный Issue** с подробностями эксплуатации.

Направьте отчёт напрямую разработчику:
- **Email**: [info@csl.by](mailto:info@csl.by)
- **Тема письма**: `[SECURITY] 1C Server Monitor: <краткое описание>`

По возможности приложите шаги воспроизведения, версию приложения и оценку потенциального воздействия.

---

## Рекомендации по безопасной эксплуатации в production

1. **Учётные данные кластера 1С**:
   - Поле пароля администратора кластера хранится только в оперативной памяти на время работы приложения и **не сохраняется** в `%LocalAppData%\1CServerMonitor\settings.json`.
   - При передаче параметров в `rac.exe` учётные данные передаются в аргументах запуска дочернего процесса на время выполнения команды.
2. **Опасные административные операции**:
   - Завершение сеансов, остановка фоновых заданий, перезапуск служб и принудительное завершение `rphost.exe` защищены явным вводом контрольных фраз (`ПОДТВЕРЖДАЮ` / `УБИТЬ RPHOST`).
   - Ограничивайте доступ к RDP/консоли сервера 1С только уполномоченным администраторам.
3. **Персональные и служебные данные в отчётах**:
   - Выгружаемые HTML-отчёты и CSV-логи содержат имена пользователей, компьютеров, баз и фрагменты контекста 1С. Храните отчёты в защищённых каталогах и не публикуйте их в открытых источниках без обезличивания.
4. **Проверка целостности сборок**:
   - Сверяйте контрольные суммы `SHA-256` из `SHA256SUMS.txt` при развёртывании релизов на продуктивные серверы.
